## Lecture 21: The Classical View vs. Modern Understanding

### 1. The Classical Paradigm: Bias-Variance Tradeoff

Before deep learning, the standard view of generalization was the **bias-variance tradeoff**:

| Term | Definition | Problem |
|------|------------|---------|
| **Bias** | Error from wrong assumptions | High bias = underfitting |
| **Variance** | Error from sensitivity to training data | High variance = overfitting |

**The Classical Solution**: Find the "sweet spot" model complexity where total error is minimized.

**The Deep Learning Challenge**: Modern networks have far more parameters than data points—yet they generalize. This breaks classical theory.

### 2. The Overparameterized Regime

**Key Insight**: In modern deep learning, we operate in a regime where:

- Number of parameters ≫ Number of training examples
- Training error can reach zero (interpolate the data)
- Yet test error continues to decrease with more parameters

**The Double Descent Phenomenon** (Belkin et al., 2019):
- Test error first decreases, then increases near interpolation threshold
- Then **decreases again** in the overparameterized regime
- This violates classical U-shaped bias-variance curve

### 3. Effective Capacity ≠ Raw Capacity

**Raw Capacity**: Number of parameters, VC-dimension (classical measure)

**Effective Capacity**: What the model can actually learn given:
- Optimization algorithm constraints
- Architecture inductive bias
- Training data distribution

**Crucial Point**: Two models with identical raw capacity can have *wildly different* effective capacity based on architecture and optimization.

### 4. Implicit Bias of Optimization

**Definition**: The tendency of an optimization algorithm to prefer certain solutions over others, even when multiple solutions achieve zero training error.

**Examples**:
- **SGD bias**: Prefers "flat minima" over "sharp minima"
- **Gradient descent** on linear networks: Moves toward minimum norm solution
- **Adam**: Different adaptive bias than SGD

**Why This Matters**: The optimizer acts as an implicit regularizer, shaping which solution the network finds among infinitely many possible solutions.

### 5. Inductive Bias of Architectures

**Definition**: Built-in assumptions about the data structure.

| Architecture | Inductive Bias |
|--------------|----------------|
| CNN | Locality, translation invariance |
| RNN/LSTM | Temporal continuity, sequential processing |
| Transformer | Permutation equivariance (without position), global interactions |
| GNN | Permutation equivariance on graph nodes |

**Key Equation** (from slides):
$$\frac{\partial L}{\partial W_1} = \prod_{l=1}^L f'(z_l)W_l$$

This product reveals the **optimization bias** imposed by architecture depth.

## Lecture 22: Trainability and Initialization

### 1. The Fundamental Problem: Gradient Instability

**Vanishing Gradients**: 
- Occurs when $|f'(z_l) \cdot W_l| < 1$ for many layers
- Product across layers → exponentially small
- Early layers learn at exponential slowdown

**Exploding Gradients**:
- Occurs when $|f'(z_l) \cdot W_l| > 1$ for many layers
- Product across layers → exponentially large
- Causes numerical overflow, NaN loss values

**Chain Rule Intuition**:
For a 50-layer network, each layer's gradient is the product of 49 Jacobians. If each Jacobian's norm is 0.9, total scaling is $0.9^{49} \approx 0.005$ — signal effectively gone.

### 2. Why Sigmoid/Tanh Failed

**Sigmoid derivative**: $\sigma'(z) = \sigma(z)(1-\sigma(z)) \in [0, 0.25]$

Maximum at $z=0$: $\sigma'(0) = 0.25$

Even in the best case, with weight $W=1$:
$$|\sigma'(z) \cdot W| \leq 0.25$$

Product over 50 layers: $0.25^{50} \approx 7.9 \times 10^{-31}$ — completely vanished.

**Why ReLU Helped**:
$$f'(z) = \begin{cases} 1 & \text{if } z > 0 \\ 0 & \text{if } z \leq 0 \end{cases}$$

For active neurons (about half), $|f'(z) \cdot W| = |W|$. With proper initialization keeping $|W|$ near 1, gradients propagate without exponential decay.

**The Dying ReLU Problem**: If a neuron's input is always negative, its gradient is always 0 — it dies permanently.

### 3. Variance Propagation and Initialization

**Goal**: Keep $\text{Var}(a_l) \approx \text{Var}(a_{l-1})$

**Derivation** (for linear layer with zero-mean inputs):
$$\text{Var}(a_l) = \text{Var}\left(\sum_{i=1}^n W_i a_{l-1,i}\right)$$

Assuming independence of $W$ and $a_{l-1}$, and zero means:
$$\text{Var}(a_l) = n \cdot \text{Var}(W) \cdot \text{Var}(a_{l-1})$$

Where $n = \text{fan}_{\text{in}}$ (number of inputs to the layer).

**To maintain constant variance**:
$$n \cdot \text{Var}(W) = 1 \quad \Rightarrow \quad \text{Var}(W) = \frac{1}{n}$$

### 4. Xavier/Glorot Initialization (2010)

**Formula**:
$$\text{Var}(W) = \frac{1}{\text{fan}_{\text{in}}}$$

**For uniform distribution** (common implementation):
$$W \sim \mathcal{U}\left[-\sqrt{\frac{6}{\text{fan}_{\text{in}} + \text{fan}_{\text{out}}}}, \sqrt{\frac{6}{\text{fan}_{\text{in}} + \text{fan}_{\text{out}}}}\right]$$

**When to use**: tanh, sigmoid, linear activations

### 5. He/Kaiming Initialization (2015)

**The ReLU Correction**: Half the activations are zero, so effective variance halves.

**Derivation** for ReLU:
$$\text{Var}(a_l) = \frac{1}{2} \cdot n \cdot \text{Var}(W) \cdot \text{Var}(a_{l-1})$$

Setting this equal to $\text{Var}(a_{l-1})$:
$$\text{Var}(W) = \frac{2}{n} = \frac{2}{\text{fan}_{\text{in}}}$$

**Formula**:
$$\text{Var}(W) = \frac{2}{\text{fan}_{\text{in}}}$$

### 6. Why Initialization is Only a Temporary Fix

**The Problem**: Initialization ensures good signal propagation at step 0. But during training:

1. Weights change (and variance changes with them)
2. Input distributions to layers shift (covariate shift)
3. Later layers receive constantly changing inputs
4. Activations can still saturate

**Evidence**: Even with good initialization, as training proceeds:
- Gradients shrink
- Layers become saturated
- Training slows down

**Visual signs** (from lecture slide 18):
- Gradients shrink during training
- Layer saturation occurs
- Training becomes extremely slow

## Lecture 23: Normalization and Residual Networks

### 1. Batch Normalization (2015)

**The Core Insight**: Instead of hoping statistics stay stable, **enforce stability** by normalizing activations during training.

**Algorithm** (for each mini-batch $B = \{x_1, \dots, x_m\}$):

| Step | Operation | Purpose |
|------|-----------|---------|
| 1 | $\mu_B = \frac{1}{m}\sum_{i=1}^m x_i$ | Batch mean |
| 2 | $\sigma_B^2 = \frac{1}{m}\sum_{i=1}^m (x_i - \mu_B)^2$ | Batch variance |
| 3 | $\hat{x}_i = \frac{x_i - \mu_B}{\sqrt{\sigma_B^2 + \epsilon}}$ | Normalize to mean 0, var 1 |
| 4 | $y_i = \gamma\hat{x}_i + \beta$ | Learnable scale/shift |

**Why This Works**:

| Problem Without BN | Solution With BN |
|-------------------|------------------|
| Internal covariate shift | Normalization makes distribution ~ N(0,1) |
| Need careful initialization | BN stabilizes even with bad init |
| Small learning rates required | Can use large LRs (10-100x bigger!) |
| Loss landscape has narrow valleys | BN smooths landscape |

**Conditioning Improvement**:
- **Bad conditioning**: Narrow curved valleys → GD zig-zags
- **Good conditioning**: Circular valleys → GD goes straight to minimum

**Optimization vs. Regularization Debate**:
- BN is **primarily an optimization technique**
- The regularization effect is a side benefit (due to batch-dependent noise)

### 2. The Degradation Problem (Pre-2015)

**The Surprising Finding** (He et al., 2015):
- Networks deeper than ~20-30 layers had **worse training error**
- Not just overfitting (test error) — training error itself increased
- This violated the intuition that deeper networks should at least match shallower ones

**Why It Was Surprising**:
In theory, if you add more layers, you can set them to learn identity mapping. Deeper network should be at least as good.

**The Reality**: SGD couldn't find the identity mapping solution from random initialization.

### 3. Residual Connections (ResNet, 2015)

**The Innovation**: Change what the layer learns.
- **Traditional**: $H(x) = \text{(learned mapping)}$
- **Residual**: $H(x) = x + F(x)$, where $F(x)$ is the residual

**Forward Pass**:
$$y = F(x, \{W_i\}) + x$$

**Backward Pass** (gradient flow):
$$\frac{\partial L}{\partial x} = \frac{\partial L}{\partial y} \cdot \frac{\partial y}{\partial x} = \frac{\partial L}{\partial y} \cdot (1 + \frac{\partial F}{\partial x})$$

**The Critical Insight**: The identity "1" provides a **gradient highway** that bypasses the residual branch entirely.

**Numerical Example** (from slide 44):
For $\frac{\partial F}{\partial x} = 0.01$:

| Architecture | Gradient Multiplier for 1 layer | For 50 layers |
|--------------|-------------------------------|---------------|
| Non-residual | $0.01$ | $0.01^{50} \approx 1 \times 10^{-100}$ |
| Residual | $1 + 0.01 = 1.01$ | $1.01^{50} \approx 1.64$ |

**Result**: Residual networks don't suffer from vanishing gradients at all.

### 4. Identity Mapping: Why It's So Powerful

**If the optimal function is identity**:
- Non-residual: Must learn identity from scratch (hard for SGD)
- Residual: Just set $F(x) = 0$ (easy — weights go to zero)

**If the optimal function is near identity**:
- Residual network starts near optimal and learns small corrections
- Creates implicit bias toward low-complexity solutions

**Ensemble Interpretation**: A ResNet with skip connections behaves like an **ensemble of shallow paths** of different lengths.

### 5. ResNet-152: The Breakthrough

**Scale**: 152 layers (previous practical limit was ~30)

**ImageNet 2015**: Won by a large margin

**Impact**: One of the most cited ML papers of all time

**Key Lesson**: "Depth was not the problem. Optimization was."

### 6. Modern Usage (2026)

**Where residuals appear**:
- **Transformers**: Every block has residuals
- **Diffusion models**: U-Net architectures with skip connections
- **LLMs**: GPT, LLaMA, Claude — all residual
- **VLMs**: Multimodal models use residuals

**Typical Transformer block**:
```
1. Attention
2. Residual connection (Add)
3. LayerNorm
4. Feedforward
5. Residual connection (Add)
6. LayerNorm
```

## Lecture 24: Optimization Landscape and Modern Implications

### 1. Flat vs. Sharp Minima

**Geometric Intuition**:

| Minima Type | Loss Landscape | Generalization |
|-------------|----------------|----------------|
| **Sharp** | Rapid increase when moving away | Poor (sensitive) |
| **Flat** | Wide low-loss region | Better (robust) |

**Why Flat Minima Generalize Better**:
- Small parameter changes don't increase loss
- Test data variations won't cause catastrophic errors
- Corresponds to simpler, more stable functions

**Sharp Minima Problem**:
- Loss increases rapidly with small parameter shift
- Overfits training data noise
- Sensitive to perturbations

### 2. SGD Noise Bias

**The Mechanism**: SGD's stochastic gradient estimates add noise to the optimization trajectory. This noise:
- Helps escape sharp minima (high curvature = noise pushes you out)
- Allows settling into flat minima (low curvature = noise doesn't disrupt)

**Implicit Regularization**: Even without explicit regularization terms, SGD biases toward flat minima.

### 3. Conditioning and Optimization Geometry

**Good Conditioning**:
- Hessian eigenvalues are similar in magnitude
- Loss contours are circular
- Gradient points toward minimum
- Fast convergence

**Bad Conditioning**:
- Hessian eigenvalues vary widely
- Loss contours are narrow ellipses
- Gradient zig-zags
- Slow convergence, requires small learning rates

**How Architecture Affects Conditioning**:
- Residual connections → better conditioning
- Batch/Layer Normalization → better conditioning
- Proper initialization → better conditioning (initially)

### 4. Architecture- Optimization- Generalization Chain

From slide 10:

```
Architecture → gradient flow & conditioning
     ↓
shapes optimization trajectory
     ↓
selects certain minima
     ↓
minima geometry affects generalization
```

**Key Takeaway**: Architecture is implicit regularization **via optimization**. You can't separate them.

### 5. The Scaling Era (2017-Present)

**Phase Progression**:

| Phase | Years | Key Achievement |
|-------|-------|-----------------|
| 1 | Pre-2010 | Shallow networks only, optimization unstable |
| 2 | 2010-2015 | Xavier, ReLU, BatchNorm → deep CNNs trainable |
| 3 | 2015 | ResNet → ultra-deep networks (152 layers) |
| 4 | 2017+ | Transformers + residuals + LayerNorm |
| 5 | 2020+ | Scaling laws → LLM explosion |

**The Core Thesis**:
> "Earlier: Architecture enables optimization. Now: Stable optimization enables scaling."

**Why Scaling Works**:
1. Residuals provide gradient highways
2. Normalization maintains stable distributions
3. Attention enables parallel computation
4. All combine to make training stable at massive scales

### 6. What Makes Scaling Work (Slide 65 analysis)

**Without**:
- Good initialization
- Normalization
- Residual connections

**Scaling would fail** because:
- Gradients would vanish/explode
- Training would be unstable
- Loss landscapes would be ill-conditioned

**Transformers succeeded because they combined**:
1. Stable optimization (residuals + norm)
2. Global information flow (attention)
3. Massive parallelization (hardware friendly)

### 7. Key Philosophical Takeaway (Slide 68)

> "Optimization is the Bottleneck, Not Expressivity"

**Implications**:
- Neural networks can represent practically any function (Universal Approximation Theorem)
- The real challenge is whether optimization can **find** that function

**Therefore**:
- Architecture is not just about representation — it defines how learning happens
- The most successful architectures are not just expressive but **optimization-friendly**
- Future progress depends on making optimization stable enough to scale further

## Exam Practice Problems

### Problem 1: Gradient Analysis

A 100-layer network uses ReLU activations. Each weight matrix $W_l$ has spectral norm (largest singular value) = 0.95.

**(a)** For a standard network (no residuals), estimate the gradient scaling factor from layer 100 to layer 1.

**Solution**: With ReLU, $f'(z)=1$ for active neurons. Gradient scales as $\|W_1\|\|W_2\|\cdots\|W_{99}\| \approx 0.95^{99} \approx 0.006$. This will cause vanishing gradients.

**(b)** With residual connections, what is the scaling factor?

**Solution**: Each residual block adds 1: scaling $\approx 1 + 0.006 \approx 1.006$ for the identity path. The residual path still vanishes, but the identity path provides a gradient highway.

**(c)** What learning rate would you recommend for each architecture?

**Solution**: Standard network needs extremely small LR ($<10^{-3}$) to avoid exploding gradients at early layers. ResNet can use large LR (up to 0.1-1.0) due to stable gradients.

### Problem 2: Initialization Design

You are designing a network with 1024 input units, 512 output units, and tanh activation.

**(a)** Using Xavier initialization, what variance should you use?

**Solution**: $\text{Var}(W) = \frac{1}{\text{fan}_{\text{in}}} = \frac{1}{1024}$ for uniform distribution, or range $\pm\sqrt{6/(1024+512)}$

**(b)** If you switched to ReLU activation, how would the initialization change?

**Solution**: He initialization: $\text{Var}(W) = \frac{2}{\text{fan}_{\text{in}}} = \frac{2}{1024}$

**(c)** Why is fan_in used (and not fan_out)?

**Solution**: The variance of the output depends on the number of inputs ($n$) times weight variance. For forward propagation stability, we use fan_in. For backward propagation stability, fan_out would be used. Xavier uses average of both.

### Problem 3: Diagnosing Training Issues

You observe the following during training:
- Loss decreases very slowly
- Early layer weights barely change
- Later layer activations are very small (<0.1 in magnitude)

**(a)** What is the most likely problem?

**Solution**: Vanishing gradients. Early layers aren't learning because gradient signal is too weak.

**(b)** What would you check first?

**Solution**: Activation values and gradients at different layers. Plot gradient norms per layer.

**(c)** How would you fix it?

**Solution**: 
1. Check initialization (should be He/Xavier)
2. Add BatchNorm layers
3. Add residual connections
4. Switch to ReLU if using sigmoid/tanh

### Problem 4: Loss Landscape Analysis

You have two models:
- Model A: Sharp minima, training loss = 0.001, test loss = 0.1
- Model B: Flat minima, training loss = 0.01, test loss = 0.02

**(a)** Which model generalizes better?

**Solution**: Model B. Despite higher training loss, test loss is much lower. Flat minima provide better generalization.

**(b)** Which model likely had a smaller learning rate during training?

**Solution**: Model A likely had smaller LR. Large LR helps SGD escape sharp minima.

**(c)** If you add BatchNorm to Model A, what do you expect to happen?

**Solution**: BatchNorm smooths the loss landscape, converting sharp minima to flatter ones. Test loss should decrease.

### Problem 5: Depth and Optimization

Explain why the following statement is false: "Since Transformers have global attention from layer 1, they don't need depth."

**Solution**: Depth is still important for:
- Building hierarchical representations
- Learning compositional structure
- Capturing long-range dependencies that require multiple transformations
- Emergent properties (e.g., DINO's segmentation only appears in deep ViTs)
