# Part 1: The Data Labeling Crisis (Lecture 29)

## 1.1 The Fundamental Problem: Supervision Doesn't Scale

**The Core Question from Slide 3**:
> "We now have powerful architectures (Transformers), massive compute, huge datasets (internet). But... who provides the labels for trillions of data samples?"

**The answer is NOT "humans label everything"** — that approach broke years ago.

### The ImageNet Story: A Miracle of Logistics

Before 2012, AI research was stuck not because models weren't big enough, but because **we didn't have enough labeled data** to train them without overfitting .

**How ImageNet was built** (2008-2010):
- **The Manpower**: 49,000 workers from 167 countries
- **The Tool**: Amazon Mechanical Turk (MTurk) — a marketplace where "Turkers" are paid cents for "Human Intelligence Tasks"
- **The Time**: 2.5 years
- **The Scale**: Filtered 160 million candidate images → final set of 14 million labeled images across 22,000 categories
- **The Verification**: Every image labeled by 3+ workers for consensus

**The Cost Reality Check** (from Slide 9):

For 1 million images:
- (1,000,000 images) × (10 seconds/image) × (1/3600 hours/second) × ($15/hour) = **$41,667**

For 1 billion images:
- Same calculation = **$41,666,667** (over $40 million!)

*And real costs are 3x higher* due to benefits, payroll tax, crowdsourcing fees, task setup time, etc.

### Why Supervised Learning Hit a Wall

**Three Fundamental Limitations** (from Slide 9):

| Problem | Explanation |
|---------|-------------|
| **Financial Wall** | Simple image labeling = $0.01-0.05 per label; medical imaging (CT scans for cancer) = $3-5 per label AND requires actual doctors |
| **The "80/20" Rule** | 80% of AI project time = data wrangling (cleaning, labeling); only 20% = actual innovation |
| **Internet Scale** | Humans can label millions; internet generates **billions daily**. The math doesn't work. |

## 1.2 Attempted Solutions That Weren't Enough

### Synthetic Data (The "Simulation" Solution)

**The Idea**: Use game engines (GTA, Unity) to generate labeled data automatically. The computer "knows" where pedestrians are in the code — labels are free.

**Why It Failed**: The **"Reality Gap."** Models trained in simulations fail in the messy, unpredictable real world because simulations aren't diverse enough.

### Active Learning (The "Smart Sampling" Solution)

**The Idea**: Model looks at 1 million unlabeled images, picks the 1,000 it's most "uncertain" about. Humans label only those.

**Why It Failed**: Still requires a human in the loop. Made labeling more efficient but didn't solve needing a human to define "truth" for every task.

### Weak Supervision (The "Rough Guess" Solution)

**The Idea**: Use hashtags (#sunset, #blessed) or captions as "labels." If it's tagged #sunset, assume there's a sun.

**Why It Failed**: Too noisy. "#blessed" rarely indicates religious content. Signal-to-noise ratio too low for high-level reasoning.

### Transfer Learning (The "Hand-Me-Down" Solution)

**The Idea**: Train on ImageNet, "recycle" that knowledge for lung tumor detection.

**Why It Failed**: Still needed that first massive hand-labeled "Source Dataset."

## 1.3 The Breakthrough Question

> "You are in need of not data but 'supervision' to train your network. How to get that supervision signal?" — Slide 14

**The Answer**: **Self-Supervised Learning (SSL)**


# Part 2: Self-Supervised Learning (SSL) Deep Dive (Lecture 29-30)

## 2.1 What is Self-Supervised Learning?

**Core Definition** (from Slide 23):
> "SSL trains models to predict some naturally-occurring signal in the raw data rather than human annotations."

**Key Distinction**:

| Paradigm | Input | Supervision | Example |
|----------|-------|-------------|---------|
| Supervised Learning | (x, y) | Human labels | "This is a cat" |
| Unsupervised Learning | x only | None (just finds structure) | Clustering |
| **Self-Supervised Learning** | x only | **Signal from data itself** | Predict next word, masked patch |

**The Insight**: The data contains its own "ground truth" — we just need to formulate the right prediction task.

## 2.2 The SSL Pipeline: Pretext → Transfer

**Step 1: Pretext Task** (training phase)
- Train network on a task that doesn't require labels
- The task is created from the data itself
- Example: Predict missing word in sentence, or predict rotation angle of image

**Step 2: Transfer** (downstream phase)
- Take the trained encoder (the "feature extractor")
- Use it for real tasks via:
  - **Linear probing**: Train only a new classification head on top of frozen features
  - **Fine-tuning**: Unfreeze and continue training on labeled data
  - **k-NN**: Nearest neighbor classification in feature space
  - **Zero-shot**: No training at all! (CLIP style)

## 2.3 Categories of Pretext Tasks (from Slide 25)

### Generative Tasks (Predict part of input)
- **Autoencoders**: Reconstruct input from compressed representation
- **Masked Autoencoders (MAE)**: Predict masked patches
- **Colorization**: Predict color from grayscale
- **Inpainting**: Fill in missing regions
- **Autoregressive**: Predict next token given previous

### Discriminative Tasks (Predict something about input)
- **Rotation prediction**: What angle was this image rotated? (0°, 90°, 180°, 270°)
- **Context prediction**: Relative position of two patches
- **Jigsaw**: Unscramble shuffled patches
- **Clustering**: Group similar images (DeepCluster)
- **Contrastive learning**: Which images are different views of same source?

### Multimodal Tasks (Use additional signals)
- **Video**: Adjacent frames provide supervision
- **Sound**: Audio track paired with image
- **3D**: Depth maps or point clouds
- **Language**: Text captions paired with images (CLIP)

## 2.4 Autoencoders: The Foundation

**Architecture** (from Slide 26):
```
Input Image: x ∈ ℝᴰ (D = 224×224×3 = 150,528 for small image)
       ↓
    Encoder
       ↓
Hidden Layer: h ∈ ℝᴴ (H << D, e.g., 1000)
       ↓
    Decoder
       ↓
Reconstructed Image: x̂ ∈ ℝᴰ
```

**Loss Function** (simplest form):
$$L(x) = \|x - \hat{x}\|_2^2 = \sum_{i=1}^{D} (x_i - \hat{x}_i)^2$$

**The Limitation**: H < D is the ONLY thing forcing non-trivial representations. If H ≥ D, the network could just copy input to output (learn identity) — useless for representation learning.

### Sparse Autoencoders (from Slide 27)

**The Fix**: Add sparsity penalty even when H can be large
$$L(x) = \|x - \hat{x}\|_2^2 + \lambda \|h\|_1$$

Where $\|h\|_1 = \sum_j |h_j|$ encourages most hidden units to be zero.

**Why This Works**: Forces the network to use only a few active neurons per input, discovering efficient, interpretable features.

## 2.5 Contrastive Learning: The Breakthrough

**The Core Idea** (from Slides 72-85):

> "Similar images should have similar features; dissimilar images should have dissimilar features."

**But how do we know what's "similar" without labels?**

**The Trick**: Different augmentations of the SAME image are "similar" (positive pairs). Different images are "dissimilar" (negative pairs).

**Data Augmentation Pipeline** (BYOL-style, from Slide 80):
- Random cropping
- Color jittering (brightness, contrast, saturation, hue)
- Gaussian blur
- Solarization
- Grayscale conversion

**The SimCLR/MoCo Framework**:

For a batch of N images:
1. Create 2 augmentations of each image → 2N total views
2. Pass all views through encoder to get features
3. For each view, its positive pair = the other view of the SAME image
4. All other 2N-2 views are negatives

**Similarity Function** (cosine similarity):
$$s_{i,j} = \frac{\phi(x_i)^T \phi(x_j)}{\|\phi(x_i)\| \cdot \|\phi(x_j)\|}$$

**InfoNCE Loss** (for positive pair i,j):
$$L_i = -\log \frac{\exp(s_{i,j} / \tau)}{\sum_{k=1}^{2N} \exp(s_{i,k} / \tau)}$$

Where τ (temperature) controls the sharpness of the distribution.

**Intuition**: This is cross-entropy loss over "which of the 2N-1 other views is my positive pair?" The model must learn to identify the matching augmentation.

## 2.6 DINO: Self-Distillation with No Labels

**The Innovation** (from Slide 32 and ):

DINO (DIstillation with NO labels) uses a **student-teacher architecture**:

```
                    ┌─────────────────┐
Image ──┬──────────►│ Student Network │──► Prediction
        │           └─────────────────┘
        │                    │
        │              EMA update
        │                    ↓
        └──────────►┌─────────────────┐
                    │ Teacher Network │──► Target
                    └─────────────────┘
```

**Key Components**:

1. **Exponential Moving Average (EMA)**:
   $$\theta_{teacher} \leftarrow m \cdot \theta_{teacher} + (1-m) \cdot \theta_{student}$$
   (m close to 1, e.g., 0.996-0.999)

2. **Multi-crop strategy** (from ):
   - 2 global crops (large, ~224×224): capture overall structure
   - Several local crops (small, ~96×96): capture local details
   - Student sees ALL crops; Teacher sees ONLY global crops
   - Forces "local-to-global" correspondence learning

3. **Centering and Sharpening**:
   - Teacher outputs centered (subtract running mean) to prevent collapse
   - Temperature sharpening makes teacher produce "peakier" distributions

**The Loss** (from ):

$$\mathcal{L}(\theta_s) = \sum_{x \in \{x_1^g,x_2^g\}} \sum_{x' \in V \setminus \{x\}} H(P_t(x), P_s(x'))$$

Where H is cross-entropy, $P_t$ is teacher output distribution, $P_s$ is student output.

**Why No Collapse?** The teacher is a slower-moving average of the student, and centering + sharpening prevents the trivial solution where all outputs are identical.

### Emergent Properties of DINO (from Slide 32)

**1. Unsupervised Object Segmentation**
DINO's attention maps perfectly outline objects (birds, cars, people) against backgrounds — without ever seeing a single segmentation label!

**2. Zero-shot k-NN Classification**
The features are so well-organized that k-nearest neighbors classification works remarkably well without any training.

**3. Semantic Layout Awareness**
The model naturally separates foreground from background, sky from ground — it learned the "logic" of visual structure.

**Key Finding from DINO Paper** : These properties only emerge with:
- Vision Transformers (ViT) — NOT with ResNets
- Self-supervised training — NOT with supervised training

### DINO vs CLIP (Recent Findings, 2025-2026)

**New research from FAIR+NYU**  shows:
> "Pure Self-Supervised Learning such as DINO can beat CLIP-style supervised methods on image recognition tasks because the performance scales well with architecture size and dataset size."

**Key Findings** :
1. SSL scales **better** with model size and data size than CLIP on VQA tasks
2. SSL can learn **text-sensitive features** purely from web images containing text
3. Performance in classic vision tasks remains competitive

**Caveat**: DINO + LLaMA (>15B params) vs CLIP (7B) comparison may be asymmetric , but the trend is clear — SSL has untapped potential.

## 2.7 Masked Autoencoders (MAE)

**Paper**: He et al., "Masked Autoencoders Are Scalable Vision Learners" (2021) 

**The Core Question** (from MAE paper ):

> "What makes masked autoencoding different between vision and language?"

**Three Key Differences** :

| Aspect | Language (BERT) | Vision (MAE) |
|--------|-----------------|--------------|
| **Architecture** | Transformers natural for tokens | CNNs don't integrate mask tokens (but ViT fixes this) |
| **Information density** | High — every word matters | Low — neighboring patches are redundant |
| **Decoder role** | Predicts missing words (semantic) | Reconstructs pixels (low-level) |

**The MAE Solution** :

**1. Asymmetric Encoder-Decoder**
- Encoder: Processes ONLY visible patches (25% of image) — NO mask tokens
- Decoder: Lightweight, processes visible + mask tokens to reconstruct full image

**2. Very High Masking Ratio**
- BERT masks 15% of tokens
- MAE masks **75% of patches!**

**Why 75%?** Because images are spatially redundant. A missing patch can be guessed from neighbors unless you mask MOST of them.

**3. Reconstruction Target**
- Loss computed ONLY on masked patches (like BERT)
- MSE between predicted and actual pixel values
- With normalized pixels per patch for better quality

**Results** :
| Model | ImageNet Top-1 (fine-tuned) |
|-------|----------------------------|
| ViT-Huge (MAE pre-trained) | **87.8%** |
| Previous best (with IN1K only) | ~85-86% |

**Scaling Behavior**: MAE shows promising scaling — larger models continue improving with more data.

## 2.8 CLIP: Learning from Natural Language Supervision

**Paper**: Radford et al., "Learning Transferable Visual Models From Natural Language Supervision" (OpenAI, 2021) 

**The Core Insight** (from CLIP paper):

> "State-of-the-art computer vision systems are trained to predict a fixed set of predetermined object categories. This restricted form of supervision limits their generality."

**The CLIP Approach**:

**Dataset**: 400 million (image, text) pairs collected from the internet

**Training Objective**: Contrastive learning between image and text encoders

```
┌─────────────┐     ┌──────────────┐
│   Image     │────►│ Image Encoder│────► Image Embedding
└─────────────┘     └──────────────┘           │
                                                ↓
                                        Contrastive Loss
                                                ↑
┌─────────────┐     ┌──────────────┐           │
│   Text      │────►│ Text Encoder │────► Text Embedding
│ "a photo    │     └──────────────┘
│  of a dog"  │
└─────────────┘
```

For a batch of N (image, text) pairs:
- Create N×N similarity matrix
- Correct pairs (diagonal) should have high similarity
- Incorrect pairs (off-diagonal) should have low similarity

**Contrastive Loss** (similar to SimCLR but cross-modal):
$$L = -\frac{1}{2N} \sum_{i=1}^N \left[ \log \frac{\exp(I_i \cdot T_i / \tau)}{\sum_j \exp(I_i \cdot T_j / \tau)} + \log \frac{\exp(T_i \cdot I_i / \tau)}{\sum_j \exp(T_i \cdot I_j / \tau)} \right]$$

### Zero-Shot Classification: CLIP's Superpower

**Traditional classification**: Train on fixed classes (e.g., "cat", "dog").
**CLIP zero-shot**: 

1. For test image, create text prompts: "a photo of a {class}" for EVERY class you care about
2. Encode all prompts with text encoder
3. Encode image with vision encoder
4. Find which prompt has highest similarity → prediction

**Example**:
```
Classes: ["cat", "dog", "car", "tree"]
Prompts: ["a photo of a cat", "a photo of a dog", "a photo of a car", "a photo of a tree"]
Image of a dog → most similar to "a photo of a dog" → predicts "dog"
```

**Result**: CLIP matches ResNet-50 accuracy on ImageNet (76.2%) **without ever seeing an ImageNet training example** .

### Why CLIP Matters

1. **Flexible classification**: No fixed label set — can classify into ANY categories you describe in natural language
2. **Multimodal bridge**: Connects vision and language (enables DALL-E, Stable Diffusion)
3. **Scaling behavior**: Performance smoothly improves with more compute and data

**Limitation**: CLIP fails on fine-grained tasks (specific dog breeds) and counting tasks . It also struggles with dense predictions (segmentation) compared to DINO.

## 2.9 Evaluating SSL Models (from Slide 29)

From the evaluation guide :

**The Challenge**: "Self-supervised models need evaluation through proxy tasks or downstream tasks, not direct accuracy."

**Key Evaluation Methods**:

### 1. Linear Evaluation Protocol 
- Freeze pre-trained encoder
- Train only a linear classifier on top
- Test accuracy = representation quality

### 2. k-NN Validation 
- Use features directly for k-nearest neighbors classification
- No training at all
- Tests feature space organization

### 3. Transfer Learning Performance
- Fine-tune on downstream tasks (detection, segmentation, classification)
- Compare to supervised baselines

### 4. Robustness Testing
- Test on distribution shifts
- Corrupted images
- Different datasets

### 5. Computational Efficiency
- Training time
- Inference speed
- Memory usage

**Common Pitfalls** :
- Data leakage (evaluation data in pre-training)
- Overfitting test sets from repeated evaluation
- Single metric not sufficient — use multiple evaluations

## 3.3 Diffusion Models (Mentioned in Slides 66, 35)

**The Two Processes**:

1. **Forward diffusion process** (fixed, not learned):
   - Start with real image x₀
   - Gradually add Gaussian noise over T steps
   - x_T ≈ pure noise

2. **Reverse denoising process** (learned):
   - Start with pure noise
   - Learn to predict and remove the noise step by step
   - Reconstruct original image

**Why Powerful**:
- Simple objective (predict noise at each step)
- Stable training (unlike GANs)
- Scales well with data and compute

**Connection to Lecture Theme**: Same principle as next-token prediction in LLMs — simple objective + large scale = emergent abilities.

## 3.4 RL, RLHF, and Alignment (Lecture 32)

**Core Definitions**:

| Term | Meaning |
|------|---------|
| **Reinforcement Learning (RL)** | Learning from rewards/penalties through interaction |
| **RLHF** (Reinforcement Learning from Human Feedback) | Using human preferences as reward signal |
| **Alignment** | Making AI systems behave according to human intent |

**Why RL Matters for Modern AI**:

1. **Not for learning from raw data** — for **alignment and decision making** (Slide 35)
2. Enables **interaction** and **planning** (Slide 36)
3. Critical for **AI agents** that act in the world

**The RLHF Process** (used for ChatGPT, Claude):
1. Pre-train model on internet data (SSL phase)
2. Collect human preference data (which response is better?)
3. Train reward model from preferences
4. Fine-tune with RL (PPO) using reward model
