## Lecture 25: Architectures as Inductive Bias

### 1.2 Inductive Bias: The Core Concept

**Definition**: Built-in assumptions about data structure that guide learning toward certain patterns.

**Why Inductive Bias Matters**:

| Property | Without Inductive Bias | With Inductive Bias |
|----------|----------------------|---------------------|
| Sample complexity | High (needs more data) | Low (learns faster) |
| Generalization | Poor (learns spurious patterns) | Good (focuses on meaningful structure) |
| Data efficiency | Requires massive scale | Works with limited data |

**The Tradeoff**:
- **Strong bias**: Great for low-data regimes, but can be wrong (e.g., assuming translation invariance for data that isn't translation invariant)
- **Weak bias**: More flexible, can learn unexpected patterns, but needs more data

### 1.3 Data Structure → Architecture Mapping

**The Design Principle**: Match architecture assumptions to actual data symmetries.

| Data Type | Structure | Symmetry | Architecture |
|-----------|-----------|----------|--------------|
| Images | 2D grid | Translation | CNN, ViT |
| Text | Ordered sequence | None (order matters) | Transformer, RNN |
| Molecules | Graph | Permutation | GNN |
| Point clouds | Unordered set | Permutation + rotation | SE(3)-equivariant net |
| Time series | 1D sequence | Time shift (often) | RNN, SSM |
| Audio | 1D signal | Local + temporal | CNN + Transformer |

**Critical Insight**: "The same model capacity ≠ same learnability." Two networks with the same number of parameters can have vastly different learning curves based on how well their inductive bias matches the data.

### 1.4 CNN Inductive Bias: Translation Equivariance

**What Translation Equivariance Means**:
$$f(\text{shift}(x)) = \text{shift}(f(x))$$

If you shift the input image, the feature map shifts by the same amount.

**How CNNs Achieve This**:
1. **Parameter sharing**: Same filter applied everywhere
2. **Local connectivity**: Each neuron only looks at local region
3. **Convolution operation**: Mathematically translation equivariant

**Important Distinction**:
- **Convolutional layers**: Equivariant (output shifts with input)
- **Pooling layers**: Approximately invariant (max pooling reduces localization)
- **Fully connected layers**: Neither (global, no spatial structure)

**Overall CNN**: Neither purely invariant nor purely equivariant—combines both properties.

**Data Efficiency**:
- With translation invariance built in, CNNs need far fewer examples than MLPs
- Example: An MLP would need to learn that a cat is still a cat whether at top-left or bottom-right of image

### 1.5 ViT: The Alternative with Weaker Bias

**How ViT Works** (Dosovitskiy et al., 2021, ICLR):

1. **Patchify**: Split image into 16×16 patches (e.g., 224×224 image → 196 patches)
2. **Linear projection**: Each patch → embedding vector (patch embedding)
3. **Positional encoding**: Add information about where patch belongs
4. **Transformer encoder**: Multi-head self-attention + MLP blocks

**Key Property**: No built-in translation invariance. The model must *learn* that a dog at top-left and bottom-right are the same thing.

**The Scaling Phenomenon**:

```
Small dataset (ImageNet-1K only):
- CNN (ResNet): ~76% top-1 accuracy
- ViT: ~72% top-1 accuracy
→ CNNs win due to stronger inductive bias

Large dataset (JFT-300M, 300M images):
- CNN (ResNet): ~85% top-1 accuracy
- ViT: ~87% top-1 accuracy
→ ViT wins when scale compensates for weaker bias
```

**Interpretation** (from slide 5): "Inductive bias is not becoming obsolete—it's shifting into data + training pipelines."

### 1.6 MLP-Mixer: The Surprising Result

**Paper**: Tolstikhin et al., "MLP-Mixer: An All-MLP Architecture for Vision" (2021)

**Architecture Breakdown**:

```
Input: Image patches [num_patches, patch_dim]
                    ↓
              Linear Projection
                    ↓
         [num_patches, hidden_dim]
                    ↓
         ┌─────────────────────┐
         │   Mixer Layer        │
         │  (repeated L times)  │
         └─────────────────────┘
                    ↓
         Global Average Pooling
                    ↓
         Classification Head
```

**Mixer Layer Two Operations**:

1. **Token-mixing MLP**: Mixes information across patches (per channel)
   - Input shape: `[num_patches, hidden_dim]`
   - MLP applied across `num_patches` dimension
   - Learns relationships between patches

2. **Channel-mixing MLP**: Mixes information across channels (per patch)
   - Input shape: `[num_patches, hidden_dim]`
   - MLP applied across `hidden_dim` dimension
   - Processes features within each patch

**Key Finding** (Figure 2 from paper, slide 9):

> "Mixer improves more rapidly with data than ResNets, or even ViT."

**Implications**:
- Self-attention is not the magic ingredient
- The critical factor is ability to model **global relationships**
- Simplicity can scale well

**Performance comparison** (JFT-300M pre-training):

| Model | Top-1 Accuracy |
|-------|---------------|
| ResNet (CNN) | ~85% |
| ViT (Transformer) | ~87% |
| MLP-Mixer | ~87% (comparable to ViT) |

### 1.7 Symmetry, Invariance, and Equivariance (Deep Dive)

#### Core Definitions

**Symmetry**: A transformation of input that should not change the meaning of the problem.
- Example: Rotating a photo of a cat → still a cat
- Example: Reordering atoms in a molecule → same molecule

**Invariance**:
$$f(Tx) = f(x)$$
Output does not change when input is transformed.

**Equivariance**:
$$f(Tx) = Tf(x)$$
Output transforms in a predictable way when input is transformed.

#### Why This Distinction Matters

| Task | Requires | Example |
|------|----------|---------|
| Image classification | Invariance | Cat at any position → cat |
| Object detection | Equivariance | Bounding box shifts with object |
| Molecular property | Invariance | Same molecule regardless of atom order |
| 3D shape analysis | Equivariance | Segmentation mask rotates with object |

#### How Architectures Encode Symmetry

| Architecture | Symmetry | Mechanism |
|--------------|----------|-----------|
| CNN | Translation | Parameter sharing across space |
| GNN | Permutation | Message passing independent of node order |
| Equivariant nets | Rotation/geometric | Special kernels, group theory |
| Set models | Permutation | Symmetric functions (e.g., sum, max) |

### 1.8 Case Study: Molecular Property Prediction

**Problem**: Predict if a molecule is toxic.

**Molecule structure**: Graph (atoms = nodes, bonds = edges)

**Option 1: Transformer as Sequence**
- Serialize molecule as list of atoms (arbitrary ordering)
- Feed to Transformer

**Why This Fails**: The ordering of atoms is arbitrary. The model might learn that "atom 1 is special" when no such special atom exists.

**Results** (slide 22):

| Model | Data Size | Accuracy |
|-------|-----------|----------|
| Transformer | 10k molecules | ~65% |
| Transformer | 1M molecules | ~80% |
| GNN | 10k molecules | ~80-85% |
| GNN | 1M molecules | ~88-90% |

**Key Lesson**: Built-in symmetry (permutation equivariance) gives GNNs ∼20% better accuracy with 100× less data.

### 1.9 Case Study: 3D Object Recognition

**Problem**: Classify 3D point clouds as "chair," "table," "vase," etc.

**Symmetry**: Object is the same regardless of rotation or translation.

**Using Standard Transformer**:
- Input: 3D coordinates in some fixed orientation
- Rotate object slightly → prediction changes
- Needs dataset with all rotations (massive data requirement)
- Fails on rotated test examples

**Using Equivariant Model**:
- Built-in rotation symmetry (SE(3)-equivariant)
- Works with far less data
- Generalizes to arbitrary rotations

**Visual example** (slide 34):
- Standard model: vase (normal) → bowl (rotated 90°)
- Equivariant model: vase → vase (regardless of rotation)

### 1.10 Unified View: Geometric Deep Learning

**The Erlangen Programme analogy** (Bronstein, ICLR 2021 keynote):
- Geometry defines space by its symmetries (Erlangen Programme)
- Similarly, deep learning architectures are defined by the symmetries they respect

**Unified Framework**:

| Inductive Bias | Grid (images) | Group (3D) | Graph (molecules) | Geodesic (manifolds) |
|----------------|---------------|------------|-------------------|----------------------|
| Symmetry group | Translation | Rotation (SE(3)) | Permutation | Isometry |
| Architecture | CNN | Equivariant net | GNN | Geodesic CNN |

**Key Quote** (slide 38):
> "CNN, GNN, Transformers → all seen through one principle—different ways of respecting symmetries in data."

## Lecture 26: Representation Learning and Hierarchy

### 2.1 The Hierarchical Nature of Deep Learning

**Key Principle**: Neural networks learn layered representations through progressive abstraction.

**CNN Hierarchy** (visualized through feature inversion):

| Layer | Learns | From Lecture 33 slides |
|-------|--------|------------------------|
| Layer 1 | Edges, corners, colors | Simple oriented lines |
| Layer 2 | Textures, patterns | Repetitive motifs |
| Layer 3 | Object parts | Wheels, eyes, ears |
| Layer 4 | Whole objects | Dogs, cars, faces |
| Layer 5 | Scene context | Indoor/outdoor, relationships |

**Transformer Hierarchy** (for language):

| Layer | Learns |
|-------|--------|
| Early | Token-level, local syntax |
| Middle | Phrase-level, semantics |
| Deep | Sentence-level, reasoning |

**GNN Hierarchy**:

| Layer | Learns |
|-------|--------|
| Layer 1 | Local neighborhoods |
| Layer 2 | Motif patterns |
| Layer 3 | Global graph structure |

**Why Depth Matters**:
- Not just capacity—each layer can build upon previous abstractions
- Depth = compositional representation learning
- Without depth, cannot learn hierarchical features

### 2.2 Feature Engineering Evolution

**Traditional ML Pipeline**:
```
Raw data → Hand-crafted features → Learning algorithm → Prediction
```
- Features designed by human experts
- Feature extraction independent of learning
- Domain knowledge required for each task

**Modern DL Pipeline**:
```
Raw data → End-to-end neural network → Prediction
```
- Features learned automatically
- Architecture determines what features *can* emerge
- Inductive bias replaces explicit feature engineering

**Key Insight**: "We don't engineer features anymore—we engineer architectures that decide what features can emerge."

### 2.3 Structured vs Unstructured Data

| Data Type | Examples | Traditional Approach | Deep Learning Role |
|-----------|----------|---------------------|-------------------|
| Structured (tabular) | Databases, spreadsheets | Classical ML (XGBoost, Random Forest) | Less successful due to lack of structure |
| Unstructured | Images, text, audio | Manual feature extraction | Highly successful—learns features automatically |

**Why DL Excels at Unstructured Data**:
- No human can hand-craft features for all image patterns
- DL discovers patterns automatically from data
- Hierarchical representation matches natural structure of images/text

## Lecture 27: Inductive Bias vs Scale

### 3.1 The Fundamental Tradeoff

**Key Question**: When should we use strong inductive bias (CNNs) vs weak bias (Transformers)?

**Strong Bias (CNNs)**:
- ✅ Works well with small data (10k-100k examples)
- ✅ Fast learning (less data needed)
- ❌ May miss patterns that violate assumptions (e.g., long-range dependencies)
- ❌ Design choices may be suboptimal for new domains

**Weak Bias (Transformers)**:
- ✅ Flexible—can learn any pattern (given enough data)
- ✅ One architecture works across domains (text, images, audio, graphs with modification)
- ❌ Requires massive data (millions to billions of examples)
- ❌ Computationally expensive

### 3.2 When Scale Compensates for Weak Bias

**The ViT Experiment (Dosovitskiy et al., 2021)**:

From Figure 3 in ViT paper (slide 7):

```
Pre-training dataset size → Accuracy on ImageNet transfer

CNN (BiT-ResNet):
- Small: 10M → 75%
- Medium: 30M → 80%
- Large: 300M → 85%

ViT:
- Small: 10M → 65%  (worse than CNN)
- Medium: 30M → 75%  (still worse)
- Large: 300M → 87%  (better than CNN!)
```

**Interpretation**: With enough data, ViT's flexibility allows it to learn spatial structure that CNNs have built-in. But it needs 10-30× more data to do so.

**The Pareto Frontier** (Figure 2 in MLP-Mixer, slide 9):
- At low compute budgets: CNN wins
- At high compute budgets: MLP-Mixer, ViT, and CNNs all converge
- Best architecture depends on available resources

### 3.3 Industry Relevance

**Most production AI systems today** (slide 51):
- Are scaling-based (LLMs, VLMs)
- Trade compute for flexibility
- Use Transformers as universal architecture

**Decision Framework**:

| Scenario | Recommended Architecture | Why |
|----------|------------------------|-----|
| Small dataset (<100k examples) | CNN (for images), GNN (for graphs) | Strong bias needed |
| Medium dataset (100k-10M) | Hybrid (CNN + attention) | Balance bias and flexibility |
| Large dataset (>10M) | Transformer/ViT | Scale compensates for weak bias |
| Multi-modal | Transformer | One architecture for all |

## Lecture 28: Architectures in the Era of Scaling

### 4.1 What Makes an Architecture Scalable?

**Four Key Factors** (from slide 57):

#### 1. Parallelism
- How many computations can be executed simultaneously?
- **Sequential dependencies** limit parallelism

| Architecture | Parallelism | Limitation |
|--------------|-------------|------------|
| Transformer | Fully parallel (within layer) | Across layers still sequential, but pipeline parallelism helps |
| RNN | Sequential (step t depends on t-1) | Fundamental bottleneck |
| CNN | Parallel within layer, sequential across layers | Depth creates sequential dependency |

#### 2. Optimization Stability
- Can we train with large batches and high learning rates?
- Do gradients vanish/explode with scale?

**Winner**: Transformers (residuals + LayerNorm ensure stability)
**Loser**: Early RNNs (vanishing gradients), Plain CNNs (degradation)

#### 3. Hardware Efficiency
- Does the architecture match GPU strengths (matrix multiplication)?
- Parameter count vs FLOPs vs memory

**Winner**: Matmul-heavy architectures (Transformers, MLP-Mixer)
**Loser**: Operations not well-supported on GPUs (some RNN variants)

#### 4. Modular & Homogeneous Design
- Is the architecture composed of identical blocks?
- Easier to distribute across devices

| Architecture | Uniformity |
|--------------|------------|
| Transformer | HIGH (same block repeated) |
| MLP-Mixer | HIGH (same mixer layer) |
| CNN | MODERATE (different: conv, pool, FC) |
| RNN | LOW (no modular stacking originally) |

### 4.2 Why Transformers Dominate Scaling

**The Perfect Storm** (slide 65 analysis):

1. **Fully parallel computation** (within layer—all tokens processed simultaneously)
   - Enables massive GPU utilization
   - Scales to thousands of devices

2. **Stable gradients** (residuals + normalization)
   - No vanishing/exploding gradients even with 100+ layers
   - Enables training giant models (GPT-3: 96 layers)

3. **Uniform architecture** (identical blocks)
   - Simple to stack more layers
   - Easy to distribute (each block can run on different devices)

4. **Hardware alignment** (matrix multiplication heavy)
   - GPUs excel at matmul
   - FlashAttention optimizes memory

5. **Flexible across domains** (minimal assumptions)
   - Works for text, images (ViT), audio, graphs (with modification)
   - One architecture to rule them all

### 4.3 Do Transformers Need Depth?

**Common misconception**: "Transformers have global attention from layer 1, so depth isn't needed."

**Reality**: Depth is still crucial:

1. **Hierarchical representation**: Single attention layer cannot learn composition
2. **Performance scaling**: BERT (12 layers) < BERT-large (24 layers) < GPT-3 (96 layers)
3. **Emergent properties**: DINO's segmentation only appears in deep ViTs
4. **Reasoning ability**: Chain-of-thought requires sequential processing through depth

**Evidence from DINO paper** (Caron et al., 2021):
- ViT-Small (12 layers): 74.0% linear accuracy
- ViT-Base (12 layers, wider): 78.2%
- ViT-Large (24 layers): 80.1%
- ViT-Huge (32 layers): 80.7%

Depth matters even with global attention.

### 2. Tolstikhin et al., "MLP-Mixer: An All-MLP Architecture for Vision" (2021)

**Focus**: Introduction, Section 3

#### Introduction (Quick read)

**Key claims**:
- Convolutions and attention are not necessary for competitive performance
- MLP-Mixer achieves SOTA with only MLPs
- Performance improves with data scale

**The Mixer Layer**:

```
Mixer Layer:
  Input: X ∈ R^{S×C} (S patches, C channels)
  
  Token-mixing:
    X ← X + W_2·σ(W_1·LayerNorm(X)^T)^T
    (MLP applied across S dimension)
  
  Channel-mixing:
    X ← X + W_4·σ(W_3·LayerNorm(X))
    (MLP applied across C dimension)
```

Where σ is GELU nonlinearity.

#### Section 3: Results

**3.1 Main results (Table 2)**:

| Model | Parameters | ImageNet top-1 |
|-------|------------|----------------|
| MLP-Mixer-B/16 | 59M | 76.4% |
| MLP-Mixer-L/16 | 208M | 80.1% |
| ViT-B/16 | 86M | 77.9% |
| ViT-L/16 | 307M | 80.7% |

**3.2 Scaling behavior (Figure 2 - IMPORTANT)**:

> "Mixer improves more rapidly with data than ResNets, or even ViT."

**Interpretation** (slide 9):
- At 3% of JFT-300M: Mixer catches ResNet
- At 10-30%: Mixer surpasses ResNet
- At 100%: Mixer matches ViT
- Even larger dataset (JFT-3B): Gap between Mixer and ViT shrinks

**3.3 Comparison**:
- Mixer performs comparably to ViT and ResNet
- Training cost: Mixer ≈ ViT (both more expensive than ResNet)
- Simplicity: Mixer uses only MLPs (no attention, no conv)

**What it tells us**: Self-attention is not the secret sauce. Global information flow + massive data + scale = performance.

## Review Questions (Comprehensive)

### From Lecture 25-26

**Q1**: You are given a point cloud classification task (3D object recognition). What symmetries are present? Why would an MLP fail? Suggest a suitable architecture.

**A1**:
- Symmetries: Permutation (order of points doesn't matter), Rotation (3D rotation doesn't change object), Translation (position in space doesn't matter)
- MLP fails because it assumes fixed input ordering; permuting points would produce different outputs
- Suitable architectures: PointNet (permutation invariant via symmetric functions), DGCNN (edge convolutions), SE(3)-equivariant networks

**Q2**: Is a CNN translation invariant or equivariant? Answer for:
- Convolution layer
- Pooling layer
- Overall CNN

**A2**:
- Convolution: **Equivariant** (output shifts same amount as input)
- Pooling: **Approximately invariant** (small shift may keep same max value)
- Overall CNN: Neither purely; outputs become more invariant as depth increases due to pooling

**Q3**: Compare CNNs and Transformers in terms of:
a) Inductive bias
b) Data efficiency
c) Scalability

**A3**:

| Aspect | CNN | Transformer |
|--------|-----|-------------|
| Inductive bias | Strong (locality, translation equivariance) | Weak (only permutation equivariance via tokenization) |
| Data efficiency | High (good with 10k-100k images) | Low (needs millions to billions) |
| Scalability | Limited (receptive field grows with depth) | High (global attention, parallel computation) |

### From Lecture 27-28

**Q4**: Which statements are TRUE? Justify.

A. "Inductive bias is becoming obsolete"
B. "Transformers eliminate the need for depth"
C. "Parallelism is a key driver of modern AI success"

**A4**:
- **A. FALSE**: Inductive bias is shifting, not obsolete. ViT still uses patch structure and position embeddings (inductive bias). For small data, bias still matters.
- **B. FALSE**: Depth remains crucial for hierarchical representations, emergent properties (DINO segmentation), and reasoning. GPT-3 has 96 layers.
- **C. TRUE**: Without parallelism, training GPT-3 would take centuries. Transformers' parallel computation is why they scale.

**Q5**: Explain the Pareto frontier in Figure 2 of MLP-Mixer (slide 9). What conclusion can be drawn?

**A5**: The plot shows accuracy vs training cost. At low compute, CNNs (ResNet) are best. At high compute, Mixer, ViT, and CNNs all converge to similar accuracy. Conclusion: Architecture choice depends on resource budget. For large-scale applications, simpler architectures (Mixer) can match more complex ones (ViT) with enough data.

**Q6**: What makes Transformers scale better than RNNs?

**A6**:
- **Parallelism**: RNNs process sequentially (step t depends on t-1); Transformers process all tokens simultaneously
- **Gradient stability**: RNNs suffer vanishing/exploding gradients; Transformers have residual connections + LayerNorm
- **Hardware utilization**: RNN ops not maximally GPU-friendly; Transformers are matrix-multiply heavy
- **Modularity**: RNNs don't stack cleanly; Transformers have identical blocks

### Data Structure and Architecture Matching

**Q7**: Match data type to best architecture with justification:

| Data Type | Best Architecture | Why |
|-----------|------------------|-----|
| Social network (users connected by friendship) | GNN | Graph structure, permutation equivariance needed |
| EKG time series | RNN, SSM | Temporal sequential dependencies |
| Set of hand landmarks (20 points, no order) | Deep Sets, PointNet | Permutation invariance required |
| Text document | Transformer | Order matters, long-range dependencies |
| Grayscale 32×32 medical images (small dataset) | CNN | Strong bias, data-limited |

**Q8**: A model trained on upright images gets 90% accuracy on test, but 50% when images are rotated 90°. What symmetry is missing? How would you fix it?

**A8**: Missing **rotation invariance**. Fixes:
1. Data augmentation: Randomly rotate training images (simplest)
2. Rotation-equivariant architecture: Group-equivariant CNNs
3. Test-time augmentation: Predict on multiple rotations, average results
