Foundations & Booting

Compilation pipeline, process memory layout, privilege rings, and how a machine goes from cold silicon to a running shell.

12 minread
Introduction.mdsource

Quick revision — the 60 second version

  • Source goes preprocessor → compiler → assembler → linker → executable
  • Process memory: code (.text) → data → bss → heap (grows up) → ... → stack (grows down)
  • 3 ways into kernel mode: system call, interrupt, program fault
  • Ring is stored in bottom 2 bits of the CS register (ring 3 = user, ring 0 = kernel)
  • Firmware (BIOS/UEFI) → POST → MBR/GPT → bootloader (GRUB) → kernel takes control → init (PID 1)
  • MBR: 4 primary partitions, 2TB max. GPT: up to 8 ZiB disks
  • init is PID 1 — the ancestor of every process; when it exits, the machine shuts down

§1 From Source Code to Executable

Before an OS can run your program, your program has to become something the OS understands: a binary. This pipeline matters for interviews because it's the backbone of "what happens when you compile a C program?" questions.

Source Code =========== hello.c (the code you wrote) | | [Preprocessor] — expands macros & headers V hello.i (source with macros/headers expanded) | | [Compiler] — source -> assembly V hello.s (assembly code) | | [Assembler] — assembly -> machine code V hello.o (object file: machine code, relocatable) | | + other object files (e.g. printf.o) | | | [Linker] — resolves symbols, merges objects V V hello (final executable file)

Each arrow is a distinct tool with a distinct job: the preprocessor is a dumb text-substitution pass, the compiler does the heavy lifting of turning C into assembly, the assembler turns human-readable assembly into raw machine code, and the linker stitches multiple object files (yours + libraries) into one runnable binary by resolving symbol references.

§2 Process Memory Layout

Once running, a process's address space is organized into segments, laid out low-to-high address:

+-----------------------+ Low Memory | Code Segment (.text) | executable instructions (read-only) |-----------------------| | Data Segment (.data) | initialized global/static vars |-----------------------| | BSS Segment (.bss) | uninitialized global/static vars |-----------------------| | Heap | grows upward -> |-----------------------| | | | v ^ | | |-----------------------| | Stack | grows downward, function frames +-----------------------+ High Memory

The heap grows towards higher addresses (via malloc/brk) and the stack grows towards lower addresses (via function calls) — they grow toward each other into the free space between them.

? Interview angle

Why separate .data and .bss if both hold global/static variables? Because .bss variables start at zero and don't need to occupy space in the executable file on disk — the OS just zero-fills that region at load time. .data variables have real initial values that must be stored in the binary.

§3 User Mode vs Kernel Mode

The CPU runs at different privilege levels. Most of the time your process runs in User Mode. There are exactly three situations that force a switch into Kernel Mode (protected mode):

System Calls

The user program explicitly asks the OS for a service (e.g. read(), fork()).

Interrupts

An external event (disk I/O completes, timer fires) demands the OS's attention.

Program Faults

An error the OS must handle — segfault, divide-by-zero, page fault.

§ Privilege rings

x86 defines 4 rings (ring 3 → ring 0). User code runs on ring 3 (least privileged); the kernel runs on ring 0. Rings 1–2 are historically used by device drivers, though most modern OSes don't use them. The ring number is stored in the bottom 2 bits of the CS (code segment) register.

ccheck your own ring
#include <stdint.h>
#include <stdio.h>

int main (int argc, char **argv) {
    uint64_t rcs = 0;
    asm ("mov %%cs, %0" : "=r" (rcs));
    printf("%d\n", (int) (rcs & 3));   // prints 3 on a normal user process
    return 0;
}

§4 The Boot Process

Turning the machine on to having a shell prompt is a chain of hand-offs, each stage trusting the next just enough to load it and jump.

1. Firmware

On power-on, the CPU executes instructions from a well-defined, fixed address — a pre-installed program sitting in read-only or flash memory. This is either the BIOS (older PCs) or UEFI (modern PCs).

2. BIOS

Basic Input/Output System. Originally burned onto ROM, later moved to flash memory so it could be rewritten without physically removing the chip. BIOS detects memory modules and external devices, sets clock speeds, monitors fans, and runs a POST (Power-On Self-Test) to verify hardware is functioning.

3. UEFI

The replacement for BIOS — backward compatible via the Compatibility Support Module (CSM). BIOS was too restrictive for large server platforms; the first open-source UEFI implementation (Tiano) was released by Intel.

4. MBR / GPT and the Bootloader

After POST, the firmware locates the primary disk and reads the first 512 bytes — the Master Boot Record (MBR) — a fixed, predefined location since the firmware knows nothing about file systems. MBR is a tiny stub program that immediately loads a larger program: the Boot Loader (on Linux, typically GRUB).

SchemeMax primary partitionsMax partition / disk size
MBR42 TB per partition
GPT (used with UEFI)effectively unlimitedup to 8 ZiB disks

The bootloader knows more about the on-disk file-system layout than the firmware does. If dual-booting, it presents the OS choice, then loads the kernel from disk into memory and jumps to its first instruction — the OS is now in control.

5. The OS takes control

  • Takes control of the hardware; switches to 32/64-bit mode if not already done
  • Creates a kernel stack, sets up the Interrupt Descriptor Table (IDT), initializes virtual memory
  • Organizes the task scheduler, file system, and other core subsystems
  • Launches user-space services
  • Loads kernel modules lazily, only as needed, via modprobe

6. Init — PID 1

The very first process the kernel spawns. It is the ancestor of every other process on the system (all future processes descend from it via fork()). When init terminates, the system shuts down.

⚠ Cold vs warm boot

Cold/Hard boot: shut down completely, then power on — every stage above runs. Warm/Soft boot (restart): skips some hardware initialization steps.

§5 Rapid-fire Recall

? Common questions

Q: What are the 4 stages a C source file goes through before becoming an executable?
A: Preprocessor → Compiler → Assembler → Linker.

Q: Name the 3 triggers for a user→kernel mode switch.
A: System calls, interrupts, program faults.

Q: Where is the current privilege ring stored?
A: Bottom 2 bits of the CS register.

Q: What's read from disk right after POST, and how big is it?
A: The MBR — the first 512 bytes of the primary disk.

Q: What is process 1, and what's special about it?
A: init — the ancestor of every process; the system shuts down when it exits.
