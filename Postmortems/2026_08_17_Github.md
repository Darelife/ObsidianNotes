- 7hr 47 mins
- Git ops, webhooks, apis, issues, PRs, actions, pages, and copilot
- ~20% error rate on web + API traffic at peak
- ~50% error rate on archive and raw content downloads
- Copilot token service traffic spiked from 7-9K RPS to 70-100K RPS (10x)
- VS Code retry bug amplified it to 10x

1. Istio sidecar pod hit its concurrency limits, and failed to autoscale. They thought that the regular k8 scaler was watching it, but the sidecar wasn't being monitored by it.
2. 4 HAProxy nodes (Load balancers) got exhausted, and degraded the path. Cuz the sidecars got slow, and the requests were waiting.
3. Optimistic retires are occurring, and is making things worse
4. Traffic is shifted to Northern Virginia, and the storm follows to N.Virginia too. Also the vscode retry bug amplifies it even more, to 10x for copilot.
5. HA Proxy gets paused in Central US, and they let the existing load reduce.
6. A PR is issued temporarily to reduce the retry logic, and auth token retries are also reduced partially. Copilot token requests get 403'd at the load balancers.

Meanwhile there were scraping attacks running on the website at the same time.

Fixes:
1. Correct auto scaling policy to account for the sidecar concurrency and capacity.
2. Fix retry limits, and backoff behaviour across all the gateways and clients
3. Address the VSCode retry bug that amplified the token traffic
4. Improve the load balancer capacity monitoring, and fail over safeguards.
